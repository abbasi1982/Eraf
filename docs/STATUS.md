## Post-gate additions (requested by the product owner, 2026-10-24)

Not part of the passed gate; outside the M0–M9 briefs, so Cursor should review them. Phase 2 is untouched.

- **App icon and Start menu name.** New icon set generated by `tools/make_icons.py` (rounded indigo-to-teal tile, photo card with sun and mountains, white voice-note pill with sound bars; preview in `tools/icon_preview.png`) written to all `Assets/*.png` and `AppIcon.ico`. Manifest display name is now "ERAF" (was "Eraf.Windows") with a one-line description. `Get-StartApps` lists the registered app as "ERAF", so the Start menu entry is the packaged app itself rather than a separate `.lnk`; it exists while the package is registered (`winapp run`), and the user can pin it. The icon was checked in a rendered preview at 24-256 px; it was **not** seen in the Start menu itself.
- **Microphone dropdown.** `MicrophoneChoice` (pure, linked into the tests: list building, remembered-device resolution, list comparison), `MicrophoneService` (device list, choice remembered in `ApplicationData.LocalSettings`), `AudioRecorder.StartAsync(deviceId)` (sets `AudioDeviceId`; a remembered device that has vanished gives a plain message and the list falls back to the default). The `ComboBox` ("Microphone", first entry "Default microphone") sits above the Record button, is hidden while recording, and refreshes on load, when opened, and before each recording.
- **Evidence.** `dotnet test`: **291 passed, 0 failed** (283 + 8 in `MicrophoneChoiceTests`). Build: 0 warnings, 0 errors. Real app (UI Automation + keyboard): the list showed Default microphone, Microphone Array (Realtek) and CABLE Output (VB-Audio Virtual Cable); the Down key picked the Realtek array and a recording with it started and stopped; the combo was hidden during recording and back after; End picked the virtual cable and a recording with it started and stopped; after an app restart the virtual-cable choice was remembered (then reset to Default).
- **Not verified:** that the recorded audio really came from the chosen device (no sound was played into each input), unplugging a chosen microphone while the app runs, Narrator reading of the new control, a Start menu visual check, and a Release/package build with the new assets.

### Many photos with one voice note, folder scanning, Settings, menu bar, themes (requested 2026-10-24; ADR-015)

- **What:** multi-select in the file list; Make ERAF on several photos and/or folders scans for photos (subfolders optional), shows the first photo, one shared voice note (record, attach, trim), then **Make N ERAF files** with an existing-file choice, progress with Stop, and a summary; Settings page; menu bar (File, Voice note, View, Tools, Help); Light/Dark/System theme.
- **Evidence:** `dotnet test` **391 passed, 0 failed** (+21 `BatchPlanningTests`: options, scanner, output names, summary); build 0 warnings, 0 errors. Real app (UI Automation): list showed `bad, sub, root1.jpg, root2.png`; Make ERAF was disabled with nothing selected and enabled with folders and photos selected. Subfolders off: 4 photos found; confirm box "This makes 4 ERAF files, each with its own photo and the same 0:03.0 voice note"; summary "3 ERAF files made, 1 could not be made" (the deliberately invalid `garbage.png` failed with a plain reason); `root1.eraf`, `root2.eraf`, `sub\s1.eraf` created, nothing for the bad photo; status "Saved: 3 ERAF files". Settings opened from Tools, the Search subfolders switch turned on (file list hidden while Settings is open; Done returns). Subfolders on: 5 photos found; "1 ERAF file made, 3 skipped because the file already existed, 1 could not be made"; `sub\deep\s2.eraf` created. Keep both: "2 ERAF files made", `root1 (2).eraf` and `root2 (2).eraf`. Replace: "2 ERAF files made, 2 replaced". Independent parser on the made files: flags 3, both digests OK, 3000 ms, and the audio SHA-256 is identical across all files of one batch (`root1`, `root2`, `s1` share one hash; a later batch re-converts the WAV so it differs). A single selected photo still opens the normal editor ("Save ERAF file"). Reset all settings restored defaults (subfolders off). Dark theme: window, menu bar, editor and the confirmation dialog rendered dark (screenshot reviewed); Light chosen on the Settings page rendered light; the default was restored at the end.
- **Not verified:** keyboard shortcuts of the menu items (Ctrl+O, Ctrl+S and others were not pressed; menu items were invoked through UI Automation), the View > Theme submenu through automation (the submenu item could not be invoked by the script; theme change was exercised from the Settings page), the "All in one folder" output mode and its folder picker, Stop during a long batch, the 2000-photo cap with real data (unit-tested only), very large batches or slow drives, folders with symbolic links, Narrator and keyboard-only use of the menu bar and Settings page, high contrast, and the look of every dialog in Light theme.

### Trim, file-manager redesign, "make ERAF from a photo" (requested 2026-10-24)

- **Trim:** "Trim voice note" (shown with any held voice note) opens a dialog with Start and End sliders (tenths of a second, keyboard operable), a live "Keeps 0:02.0 to 0:07.0 (5.0 s)" line, **Play selection**, and Trim/Cancel (`TrimDialog`, `TrimRange`, `AudioTrimService`).
- **File manager (ADR-014):** maximized window; top bar with Back, Forward, Up, Refresh, folder path box, name filter, Use camera, Import image (any folder), Open ERAF file (any folder) and **Make ERAF**; left blade (`PlacesBlade`) with Quick access and This PC drives, folders loading when expanded; right details list (`FileListPane`) with Name, Date modified, Size, Type columns, sortable, photo thumbnails, double-click or Enter to open; "Back to files" replaces "Start over". Last folder is remembered.
- **Make ERAF from a photo (item 3):** select a photo, press Make ERAF (or double-click/Enter): it starts a session with the photo, then record or attach a voice note, trim if wanted, and Save ERAF file (suggested name and folder come from the photo). Same atomic save as M6.
- **Evidence:** `dotnet test` **370 passed, 0 failed** (62 more than the previous 308: `TrimRangeTests` and `FileBrowsingTests`); build 0 warnings, 0 errors. Real app, UI Automation and real key presses: window maximized (2278x1454); address box and tree (Documents via Enter) navigate; a bad path shows "That folder does not exist..." and restores the old path; filter "real" leaves real.bmp, real.jpg, real.png; Make ERAF with real.jpg selected started a session, recorded, saved `real-made.eraf` beside the photo; Back to files showed the new file in the list; Enter on it opened it ("Opened: real-made.eraf"); Up, Back, Forward changed folders; sort headers update their accessible names; the remembered folder was restored on the next start. Trim on a 10 s tone: kept 2.0-7.0 s (voice note "0:05, 80 KB"), Cancel kept it, Play selection toggles to Stop. The earlier end-to-end smoke (import, record, play, save, export, open, unsaved prompt, five invalid fixtures, independent parser) was re-run on the new layout and passes.
- **Found and fixed on the way:** the folder tree crashed at start when its nodes used a data template with a plain C# class (replaced by text nodes); Enter on a focused row needed `PreviewKeyDown`; the Write tool turned `\uE734`-style glyph escapes into raw characters (restored).
- **Not verified:** keyboard-only walk and Narrator on the new shell (names/help text are set; not heard), high-contrast and scaling, a drive that is disconnected or slow while browsing, a folder with thousands of files (thumbnails load lazily, not measured), dragging files onto the window (not implemented), trimming a clip near the limits, dark theme look, snap/narrow window layouts (the blade is a fixed 280 px).

### Attach a saved audio file (requested 2026-10-24)

- **What:** "Attach audio file" (and "Replace with audio file" once a note exists) uses an audio file as the voice note instead of recording. AAC M4A is kept untouched; other formats are converted to AAC M4A (ADR-013). `AudioImportService`, `ErafMedia.PlanAudioImport`, workflow event `AudioAttached` (legal pairs 28 → 32).
- **Evidence:** `dotnet test` **308 passed, 0 failed** (+7 `AudioImportPlanTests`, +4 workflow pairs, +1 event in the coverage guard); build 0 warnings, 0 errors. Real app: a 3 s WAV was converted (voice info "0:03, AAC M4A, 49 KB"), played, saved; the independent parser reports flags 3, both digests OK, 3000 ms, and the exported M4A equals the audio inside the file; an exported AAC M4A attached back was kept byte for byte in a second file (audio SHA-256 equal; duration read from the file's properties, 3018 ms); a fake `.mp3` (not audio), a 100 ms WAV and an 11-minute WAV were each refused with a plain message and the existing voice note survived.
- **Not verified:** MP3/WMA/FLAC/AAC-ADTS inputs (only WAV converted), HE-AAC or ALAC inside M4A, files with video, a source near 512 MiB, closing the window during a conversion, Narrator on the new buttons.
